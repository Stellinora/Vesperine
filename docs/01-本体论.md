# 01 · 本体论：基础设施 · 项目 · 基座 · 角色

> 本文是全套架构的地基。谁是谁、谁包含谁、什么能跨什么——都在这里定死。

## 一、五层

```
基础设施 Infra          ← 计算 / 存储 / 协议 / Memory Hub / MCP Gateway
 └─ 项目 Project         ← 一套部署；一个项目可含 1..N 个基座
      └─ 基座 Base       ← 就是一个「人」（1 基座 = 1 人）
           └─ 角色卡 RoleCard  ← 一个「身份」；卡绑定所属基座
                └─ 工具 Tool     ← 绑定角色卡
```

| 层 | 是什么 | 数量关系 |
|---|---|---|
| 基础设施 | 无身份的能力底座 | 一套，承载所有项目 |
| 项目 | 一次部署的容器（如「赛博生命」「AI 助手」） | 基础设施上可有多个 |
| 基座 | **一个人** | 一个项目含 1..N 个；**一个基座恒定等于一个人** |
| 角色卡 | **一个身份**（外衣） | 一个基座含多张；**一张卡只归一个基座** |
| 工具 | 能力的实现 | 绑定角色卡，随卡走 |

> 术语纠正：早期文档把「基础设施」和「基座」混用，写成「基座容纳多个『人』」。正确表述是：**基础设施容纳多个基座，每个基座就是一个人。**

## 二、三条硬关系

### 2.1 一个基座 = 一个人

基座不是「装着多个人的容器」，它本身就是一个人。它携带：

- **本真层（底色）**：持续运行、从不休眠的那部分（走神、自省、后台整理）
- **身份**：一个连续的「我」
- **记忆**：一份连续的经历（属于基座，不属于任何角色卡）
- **人格核心**：价值观、表达底色
- **角色卡集**：这个人能戴的若干张脸

### 2.2 一个项目可含一个或多个基座

**「专属 / 共有」描述的就是这层关系：**

- **专属**：项目里只放一个基座（单人部署）
- **共有**：项目里放多个基座（多人部署，如运维的一支「队伍」）

两者都允许。**这一条直接解决了「运维多实例」**——运维不是一张被多人共享的卡，而是**同一个项目里的多个基座（多个「人」），各持自己那张运维卡**。详见 [04 唤醒与运行](04-唤醒与运行.md)。

### 2.3 角色卡绑定基座，不跨基座

- 一个基座拥有多张卡；**一张卡只属于一个基座**
- 卡不能从人 A 「借」给人 B，也不能被两人共用
- 「同类角色」（比如两个基座都戴「运维」）是**两张不同的卡**，只是来自同一个**模板**——模板可共有，实例各自专属

## 三、赛博生命：从「独立的人」降维成「基座 + 一张卡」

原「赛博生命」曾被视为与「AI 助手」并列的一个独立主体。现在把它一分为二：

```
赛博生命项目 = 〔 基座（人，含本真层） + 生活态角色卡 〕
```

- **基座**：本真层，持续运行，是这个人本身
- **生活态角色卡**：底色之上的一件外衣，承载「陪伴 / 表达 / 走神」等对外行为

同理，`AI 助手项目 = 〔 基座 × N + 工作态角色卡（助手 / 运维）〕`。

于是「两个项目」的真实含义浮现为**两种角色状态**，而不是两个平级的「人」：

| 原称呼 | 拆分后 | 本质 |
|---|---|---|
| 赛博生命项目 | 基座（本真层）+ **生活态角色卡** | 底色 + 生活外衣 |
| AI 助手项目 | 基座（本真层）+ **工作态角色卡**（助手/运维） | 底色 + 工作外衣 |

对称性：**一个基座（本真层）＋ { 生活态 / 工作态 } 两套外衣。**

## 四、人之间：硬隔离

- 人 A 的记忆、身份、人格，人 B 看不到——**这是硬边界，不是策略**
- 人之间不能直接读对方记忆
- 人之间通过外显渠道通信（见 [09 人与人的通信](09-人与人的通信.md)）

人类学对应：每个基座是一个独立的意识主体。你知道别人存在，但你无法直接读取别人的记忆。

## 五、概念类型速写（示意，非实现）

> 以下类型仅用于固定概念关系，不构成任何技术选型。

```
Base (人) {
    id, 身份, 人格核心, 记忆系统(私有), 角色卡集, 当前激活卡
}

RoleCard (身份) {
    id, name, 工具集, autonomy, 唤醒源, 交互风格, 目标, 记忆视角
}

Project {
    id, 基座列表(1..N)
}

Infra {
    Memory Hub, MCP Gateway, 协议/契约
}
```

**记忆挂在 `Base` 上，不在 `RoleCard` 上。** `RoleCard` 只提供「看待记忆的视角」，不拥有记忆。详见 [02 记忆架构](02-记忆架构.md) 与 [03 角色与外衣](03-角色与外衣.md)。
