# 12 · 极简路线：Principal · 执行体 · 租约

> 状态：**提案，未定案**。本文收敛自 2026-10 关于「手机说话、电脑执行、单 Docker、纯助手、复用 Claude Code / Codex」的讨论。
>
> 本文**不取代 00–11**。它给出另一条更薄的实现路线；若采纳，01–04、06、08 需要封存或重写。

## 一、一句话

**一个固定 Principal，一个 Docker 记忆/技能中枢，N 个客户端执行体。** 云端管身份、记忆、授权、对外通道；本地管热路径执行与短期上下文。

没有基座、本真层、角色卡、人格核心，也没有单 Principal 场景下的 A2A。「同一个人」由 **Principal id 固定**保证，不由基座对象保证。

---

## 二、极简模型

```
Principal（唯一）
 └─ Docker 中枢
      ├─ 记忆队列 / 记录者 / 世界线 / 定时整理
      ├─ 技能库（反馈闭环）
      ├─ 场景注册表（软分类）
      ├─ 调度器（按场景选执行体）
      ├─ 租约签发 / 吊销
      ├─ 高风险确认队列
      ├─ 审计汇总
      ├─ MCP Gateway
      │    ├─ 出站工具：send_qq / send_feishu / 外部 API
      │    └─ Docker 内 Agent worker（可选）
      ├─ 通道适配器（入站）
      │    ├─ QQ → 验签 → 信号
      │    └─ 飞书 → 验签 → 信号
      └─ 安全通道（客户端主动外连）
           ├─ 电脑执行体：本地文件 / shell / 本地 MCP / GUI
           └─ 手机执行体：语音 / 通知 / 传感器

客户端（电脑 / 手机）
 └─ 本地短期上下文 + 提交信号 + 召回读取 + 本地受限 Agent（编程场景）
```

## 三、与现有本体论的映射

| 原概念（00–11） | 极简路线 | 说明 |
|---|---|---|
| Infra | Docker 中枢 | 计算、存储、队列、网关、审计 |
| Project | 一次部署 | 单 Principal 部署；未来可多 Principal |
| Base | Principal | 只保留身份、记忆归属、凭证；人格核心降为可选配置 |
| RoleCard | Scene（场景） | 软分类，不再承担硬权限边界 |
| Tool | Tool + 风险属性 | 工具自带风险等级、确认要求、凭证域 |
| 内务能力 | 定时整理 | 记忆整理、技能归纳，单点运行 |
| 世界线 | 保留内核 | 只增、不可改、带来源、可审计 |
| 记忆层 | 简化投射 | 单视图或场景偏置；情感权重按需保留 |
| 经验层 | 技能库 | 保留「使用 → 记效果 → 升/降/淘汰」闭环 |
| Episode | 任务 Episode | 编程场景从「故障」改为「一次任务」 |
| A2A | 暂不需要 | 单 Principal 下无「人之间」通信；多 Principal 时恢复 |

**新增概念：执行体（Executor）、租约（Lease）、场景注册表（Scene Registry）、通道适配器（Channel Adapter）、元记忆（Meta-memory）。**

## 四、执行体

执行体是 Principal 的「手和脚」，**不拥有记忆、身份、人格、凭证**。

| 类型 | 位置 | 职责 | 约束 |
|---|---|---|---|
| Docker worker | Docker | 长任务、隔离 sandbox、编码/审查 | 由调度器拉起；不写记忆 |
| 客户端执行端点 | 电脑 / 手机 | 本地文件、语音、通知、本地 MCP、GUI | 不决策；只执行下发指令 |
| 本地受限 Agent | 客户端 | 编程热路径：读文件 → 改代码 → 跑测试 | 持租约；短期自主，无长期身份 |

### 4.1 控制流是 Pull，不是 Push

Docker 在服务器上，无法主动「进入」客户端。客户端上的 Bridge 主动向中枢建立长连接（WebSocket / 长轮询），有任务时领取，执行后回传。

```
客户端 Bridge：有任务吗？
Docker：无 → 连接挂起
Docker：有 → 下发（带 principal / scene / tool / 风险 / 确认状态）
客户端：本地执行 → 回传结果 + 审计事件
```

### 4.2 内务单点

记忆整理、技能归纳、定时巩固**只在 Docker 主执行体上跑**，不能在多个客户端各跑一份，否则经验层置信度会出现写入竞态。

## 五、租约

租约是 Docker 签发给执行体的**有时限、有范围、可吊销**的授权凭证。

```json
{
  "principal_id": "p-001",
  "client_id": "pc-01",
  "scene": "coding",
  "allowed_tools": ["fs.read", "fs.write", "shell.exec", "local_mcp.*"],
  "risk_ceiling": "medium",
  "expires_at": "2026-10-26T12:00:00Z",
  "revocable": true,
  "offline_policy": {
    "allow_local_confirm": false,
    "local_confirm_max_risk": "high",
    "require_principal_verification": true,
    "pre_issued_token_ttl": 3600
  },
  "context_bundle": {
    "project_conventions": [],
    "relevant_decisions": [],
    "pitfall_notes": [],
    "user_coding_prefs": []
  }
}
```

### 5.1 风险分级

| 风险 | 云端可达 | 云端不可达 |
|---|---|---|
| 低 | 自动 | 自动 |
| 中 | 自动 + 异步审计 | 自动 + 补录审计 |
| 高 | 云端确认 | 本地 Principal 确认（租约显式允许） |
| 极高（删库、改生产、群发） | 云端确认 + 人类 | **拒绝**，不给本地确认开口子 |

### 5.2 本地确认的三个条件

缺一不可：

1. 云端不可达；
2. 租约显式授予 `allow_local_confirm`；
3. 本地用户通过 Principal 验证（设备密钥 / 登录态 / 生物识别 / 预下发令牌）。

本地确认只对**单次动作**有效，不能批量授权，不能延长租约。确认后产生「待补录审计事件」，重连后回传云端二次校验；校验不通过标记为未授权并告警。**极高风险离线一律拒绝（fail-closed）。**

## 六、场景

场景是**软分类**，不是权限边界。它提供默认倾向，允许被单次调用覆盖。

```
Scene {
  id, name,
  style,                 // 表达底色
  default_tools,         // 先挂这些，不是只能用这些
  recall_bias,           // tool_weight / emotion_weight 偏好
  default_autonomy       // auto / approve / forbidden 的默认值
}
```

| 用途 | 说明 |
|---|---|
| 记忆召回偏置 | 工作场景偏 `tool_weight`，生活场景偏 `emotion_weight` |
| 表达与默认工具 | 决定 prompt 底色与默认工具集 |
| 审计维度 | 审计保留 `scene_id`，用于事后分析，不是权限 |

硬约束不放在场景里，而放在**工具风险属性 + 单次调用判定**：

```
每次工具调用携带：
  (principal_id, scene_id, tool_name, 风险等级, 是否人类确认)
```

权限最小化、高风险确认、审计、凭证隔离仍然保留，只是锚点从「角色卡」移到了「单次调用」。

## 七、记忆

### 7.1 写入：客户端只提交，不写记忆

客户端提交**原始信号**，不做总结、不做判断。Docker 是唯一写入者。

```json
{
  "principal_id": "p-001",
  "client_id": "pc-01",
  "seq": 1024,
  "channel_id": "desktop",
  "observed_at": "2026-10-26T10:00:00Z",
  "kind": "user_message",
  "content": "原始内容，不做语义加工",
  "source_refs": []
}
```

规则：

- **至少一次 + 幂等**：Docker 按 `(client_id, seq)` 去重，断网重发不会写重。
- **不要求到达顺序**：世界线靠时间戳对齐，不靠到达顺序。
- **提交要带身份**：Principal 凭证验签后落盘，审计记录 `client_id`。
- **回执可选**：只用于重试去重，不用于内容对齐；本地短期上下文过期即弃。

### 7.2 读取：读已落盘段，短期上下文留本地

- 会话内短期状态放客户端本地内存，不进长期记忆。
- 召回读 Docker 已落盘的记忆；队列未消费的窗口不参与召回。
- 只有「值得长期记住」的内容才提交；可由客户端按简单规则预筛，也可全量提交由 Docker 筛。

### 7.3 世界线内核

保留 `02` 的核心：客观、只增、不可改、可审计、带来源。记录者只做时间戳对齐、事件切分、实体识别、索引、去重、来源标注，不做情感判断、重要性排序、叙事重构、因果推断。

### 7.4 纯助手简化

| 原机制 | 极简路线 |
|---|---|
| 两维权重 | 可压成单一重要性权重 |
| 多视图投射 | 单视图，或只留场景召回偏置 |
| 拟人化遗忘 | 可整类砍掉 |
| 情感权重 | 可砍掉，或仅作可选偏置 |
| 经验层 | 可选；保留则反馈闭环不能省 |

### 7.5 编程场景：只存元记忆

代码、diff、日志、测试结果已经存在于 repo / git / issue / 文档中，**不抄进中枢**。

| 该记 | 不该记 |
|---|---|
| 项目级决策（为什么选这个方案） | 每次读的文件内容 |
| 踩坑记录（这个项目特有的坑） | 每轮工具调用的输入输出 |
| 项目约定（命名、结构、禁区） | 测试报错的原始日志 |
| 用户编码偏好 | 代码 diff 本身 |
| 跨会话进展摘要 | 会话内短期上下文 |

编程场景的 Episode 语义从「一次故障」改为「一次任务」：`services` → `repo/branch`，`root_cause` → `决策理由`。经验层/技能库在编程场景升为主角。

## 八、通道：QQ / 飞书

通道不是客户端 Agent，是**通道适配器**。

```
入站：QQ / 飞书消息 → 验签 → 统一信号 → 队列（带 channel_id）
出站：Agent 发言 → MCP 工具 send_message → 通道适配器 → 平台 API
```

| 情况 | 归属 |
|---|---|
| 你在 QQ 上跟 Agent 聊，Agent 以你的助手身份应答 | 同一个 Principal 的入站通道 |
| Agent 主动在群里发言、发通知、回别人 | 同一个 Principal 的出站工具（需授权） |
| QQ 上存在独立人格，有自己的记忆和连续性 | 另一个 Principal（当前不做） |

约束：

1. 入站必须验签并标 `channel_id`，否则群聊与私人对话混成无来源记忆。
2. 出站是「对外动作」，比读写本地文件风险高；至少分两档：回复当前会话自动，主动发起/群发需确认。
3. 会话归属要定：默认进同一份长期记忆，检索时按 `channel_id` 过滤；若群聊不应进私人记忆，加「通道级记忆策略」。

## 九、云端 / 本地职责

| 云端 Docker | 为什么必须在云端 |
|---|---|
| Principal 身份 + 凭证 | 唯一「一个人」的锚点 |
| 记忆队列 / 记录者 / 世界线 / 定时整理 | 单写入者，避免并发写脏 |
| 技能库 + 反馈闭环 | 跨客户端、跨会话累积 |
| 场景注册表 | 租约下发时的权威定义 |
| 租约签发 / 吊销 | 授权源头必须唯一 |
| 高风险确认队列 | 人不在本地时也能挂起等待 |
| 审计汇总 | 各客户端事件在这里合并 |
| MCP Gateway 出站工具 | 对外动作统一出口 |
| 通道适配器（入站） | QQ / 飞书验签后转信号 |
| 调度器 | 决定任务给哪个执行体 |
| Docker 内 Agent worker（可选） | 长任务、隔离 sandbox |

| 本地客户端 | 为什么不能上云 |
|---|---|
| 本地受限 Agent（Claude Code / Codex） | 编程热路径，每轮工具调用不能过网络 |
| 租约执行器 | 本地实时判工具白名单与风险 |
| 本地工具（fs / shell / 本地 MCP / GUI） | 只能在本地执行 |
| 本地短期上下文 | 会话内临时状态，不进长期记忆 |
| 信号提交 Bridge | 只负责把原始信号推给云端队列 |
| 手机轻量端点 | 语音、通知、传感器 |

**边界规则：**

- 写记忆：只有云端写。
- 授权：云端发租约，本地在租约内自主执行；超出回云端。
- 高风险：本地挂起，回云端确认；离线默认拒绝。
- 对外发言：出站走云端 MCP Gateway，入站走云端通道适配器。

## 十、安全不豁免项

极简路线砍的是「像人」，不是「可审计、可隔离、可溯源」。

| 保留 | 原因 |
|---|---|
| Principal 身份唯一 | 否则「同一个人」不成立 |
| 凭证隔离 | 服务凭证 vs 用户凭证分开 |
| 工具调用带身份 + 审计 | 哪个客户端、在什么场景下调了什么工具，必须可追溯 |
| 权限最小化 | 按工具风险等级 + 场景默认授权动态判定 |
| 高风险操作确认 | 删除 / 重启 / 群发等必须人类确认 |
| 记忆可溯源 | 每条记忆带来源与证据链 |
| fail-closed | 离线、验证失败、租约过期时默认拒绝 |

## 十三、术语增量

| 术语 | 定义 |
|---|---|
| **Principal（主体身份）** | 固定唯一的主体 id。记忆、审计、凭证、通道身份归它。极简路线用 Principal 替代 Base 作为连续性锚点。 |
| **执行体（Executor）** | Principal 的运行时执行实例。不拥有记忆、身份、人格；受租约约束。 |
| **租约（Lease）** | Docker 签发的有时限、有范围、可吊销授权凭证。 |
| **场景（Scene）** | 软分类。提供表达风格、默认工具集、召回偏置、默认授权，不是硬权限边界。 |
| **通道适配器（Channel Adapter）** | QQ / 飞书等外部通道的入站验签与格式转换层；出站走 MCP 工具。 |
| **元记忆（Meta-memory）** | 编程场景下只保留的决策、踩坑、约定、偏好、进展；不含代码、diff、日志。 |
| **单写入者（Single Writer）** | 只有 Docker 写记忆；客户端只提交原始信号。 |
