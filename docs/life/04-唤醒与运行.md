# 04 · 唤醒与运行

> 底色永不休眠；角色按需唤醒。工具集可以整体重载，内务循环不行。

## 一、底色持续运行：内务能力

§03 说「切角色 = 工具集完全重载（替换）」；本体论又说「底色从不休眠」。两者如何共存？

**答案：把「对外执行工具」和「内务能力」分开。**

```
基座（人）
 ├─ 内务能力（基座级，不属于任何角色卡，永不卸载）
 │    · 记忆整理 / 摘要 / 索引
 │    · 走神 / 自省 / 自触发
 │    · 睡眠巩固（生成经验）
 │    · 角色切换（元能力）
 │
 └─ 对外执行工具（角色卡级，随卡整体重载）
      · 助手卡：fs / 日历 / 搜索 / 邮件
      · 运维卡：k8s / log / metric / alert
      · 生活态卡：表达 / 学习 / 社交
```

- 切卡只重载**对外执行工具**
- **内务能力**用基座级元能力继续跑，不中断
- 这样「底色永不休眠」与「切角色=工具重载」不再打架

## 二、唤醒源

不同角色卡有不同的唤醒源。唤醒源是**角色卡**的属性，不是人的属性。

```
enum WakeupSource {
    UserMessage,                          // 用户消息（助手 / 生活态）
    Alert { source },                     // 告警（运维）
    Schedule { cron },                    // 定时
    Event { topic },                      // 事件总线
    Peer { from: BaseId, msg },           // 其他「人」（A2A）
    HumanRequest { op_id },               // 人类运维发起
    SelfTrigger { reason },               // 自触发（本真层，走神）
}
```

- 助手卡：用户消息、日程提醒
- 运维卡：告警、定时、事件、其他「人」、人类运维、自触发
- 生活态卡：内心冲动、走神、社交事件

## 三、运维角色：多实例 = 多基座

**关键结论**：运维不靠「一张被多人共享的卡」实现多实例——角色卡不跨基座。运维的多实例是：

```
运维项目（AI 助手项目下的一个角色形态）
 ├─ 基座 C = 人丙   → 运维卡·C（负责集群A）
 ├─ 基座 D = 人丁   → 运维卡·D（负责集群B）
 └─ 基座 E = 人戊   → 运维卡·E（负责数据库域）
```

- 每个实例是一个独立「人」（自己的基座）
- 各持自己那张运维卡（同类，来自同一**模板**，但实例各自专属）
- 它们之间的协调 = **「人」与「人」之间的 A2A**（见 [09 人与人的通信](../09-人与人的通信.md)）
- 分布式锁 / 任务抢占 / Leader 选举 = 这些「人」之间的协调问题

---

## 四、运维「人」的独有需求

即便建模为「人」，运维实例仍有与普通陪伴型「人」不同的运行特征：

| 维度 | 用户侧「人」 | 运维侧「人」 |
|---|---|---|
| 有无用户 | 有，交互式 | 无用户，自主运行 |
| 唤醒 | 用户输入 | 告警/定时/事件/其他「人」 |
| 生命周期 | 随用户开关 | 常驻/守护 |
| 输出 | 对话回复 | 动作 + 报告 + 状态变更 |
| UI | 有界面 | 无头，但有管理台 |
| 凭证 | 用户 token | 专属服务凭证 + 权限域 |

- **服务身份**：独立的 Service Account，有明确权限域，可审计、可轮换、可吊销，不随任何用户登录状态变化
- **自主分级**：`autonomy`（auto / approve / forbidden）
- **管理台另设**：运维「人」无头运行，人类运维通过管理台（本身是一个用户侧「人」）查看 Episode、审批动作、接管任务

## 五、主动汇报与打扰预算

不是所有观测都推给用户。大多数后台观测只记忆、不打扰：

```
fn should_notify(obs, user_state) -> bool {
    match obs.severity {
        Critical => true,                 // 立即
        Warning if user_state.active => true,
        Warning => false,                 // 攒着
        Info => false,                    // 只记忆，不打扰
    }
}
```

用户离开时，Agent 继续记录；回来时给一份合并摘要：
「你离开的 40 分钟里，X 服务有 3 次告警，目前已恢复，详情如下……」

## 六、三个角色的对比

| 维度 | 助手卡 | 运维卡 | 生活态卡 |
|---|---|---|---|
| **工具** | fs/日历/搜索/邮件 | k8s/log/metric/alert | 表达/学习/社交 |
| **唤醒** | 用户消息 | 告警/定时/自触发 | 内心冲动/走神 |
| **记忆视角** | 生活/偏好 | 故障/模式 | 关系/成长 |
| **交互风格** | 高效/简洁 | 严谨/汇报 | 自然/表达 |
| **在框架中的位置** | 工作态外衣 | 工作态外衣 | 生活态外衣 |

> 底色（本真层）不是这三者之一——它是**基座本身**，三者都叠在它之上。
